ÉTAPE 0 — SAUVEGARDE (5 min, obligatoire)
-----------------------------------------
a) GitHub > dépôt F1-Finger-Race > Releases > "Draft a new release" > tag "v1-avant-v2" > Publish.
   Ça fige l'état exact du code. Retour arrière possible avec un simple "git checkout v1-avant-v2"
   ou en téléchargeant le ZIP de cette release.
b) Console Firebase > Firestore Database > Règles : copie TOUT le contenu actuel dans un fichier
   firestore.rules.v1 sur ton PC. Les nouvelles règles refusent des écritures de l'ancien code
   (ex. le champ "email") : en cas de retour en arrière il faudra republier les anciennes règles.
c) App Check n'est pas encore activé : rien à sauvegarder. Le jour où il l'est (étape 3), le
   retour arrière = décocher "Appliquer" dans la console.


ÉTAPE 1 — DÉPLOYER LE CODE (5 min)
----------------------------------
- Copie tous les fichiers de l'archive à la racine du dépôt (écrase index.html, sw.js,
  manifest.json, privacy.html, icon-192.png, icon-512.png ; ajoute les nouveaux dossiers
  lang/, store/, .well-known/).
- Commit + push. GitHub Pages met 1 à 2 minutes à publier.
- Vérifie dans F12 > Console : "[F1 Finger Race] build 2026-09-01-v2". Si tu vois encore
  l'ancien build, ferme tous les onglets du jeu, rouvre : le service worker v6 remplace le v5
  au 2e chargement (il efface l'ancien cache tout seul).
- Sur ton téléphone : l'ancienne icône installée reste valable (même URL, même scope). Pour que
  le nouveau mode "standalone" (barre de statut normale, plus de message plein écran Android)
  soit pris en compte, retire l'icône puis réinstalle-la une fois.

  NOTE — l'archive contient un fichier vide ".nojekyll" : garde-le à la racine du dépôt, c'est
  lui qui permet à GitHub Pages de servir le dossier .well-known/ (les dossiers commençant par
  un point sont ignorés sans lui).


ÉTAPE 2 — RÈGLES FIRESTORE + INDEX (10 min, en même temps que l'étape 1)
-------------------------------------------------------------------------
a) Console Firebase > Firestore Database > Règles : remplace tout par le contenu de
   firestore.rules > Publier. Les anciennes collections "races" et "record_events" passent en
   lecture seule (l'ancien code ne peut plus y écrire) ; le nouveau code écrit dans "races_v2",
   "record_events_v2" et "daily".
b) Index composites à créer (Firestore > Index > Composite > Créer). Le plus simple : joue une
   course, ouvre "Records", puis F12 > Console : chaque requête sans index affiche une erreur
   "The query requires an index" avec un LIEN qui pré-remplit le formulaire. Clique, valide,
   attends 2-5 minutes. Il y en a 4 :
     races_v2           weekId (croissant) + raceKey (croissant) + time (croissant)
     races_v2           weekId (croissant) + createdAt (décroissant)
     daily              dayId (croissant)  + time (croissant)
     record_events_v2   createdAt (décroissant)   [index simple, normalement automatique]
   Tant qu'un index manque, l'écran concerné affiche juste "Classement indisponible" ; rien ne
   plante.
c) Quand tu es sûr que tout marche (quelques jours), tu peux supprimer les collections "races"
   et "record_events" (v1) depuis la console pour faire place nette. Les records perso liés aux
   comptes (collection "users") et les défis sont conservés.


ÉTAPE 3 — APP CHECK (15 min, anti-triche, à faire avant toute mise en avant publique)
--------------------------------------------------------------------------------------
a) Clé reCAPTCHA v3 : https://www.google.com/recaptcha/admin/create
   - Libellé : F1 Finger Race
   - Type : reCAPTCHA v3
   - Domaines : julien67890.github.io  ET  localhost (pour tes tests)
   - Créer > note la "Clé du site" (pas la clé secrète).
b) Console Firebase > App Check > Applications > ton application web > Enregistrer >
   fournisseur reCAPTCHA v3 > colle la CLÉ SECRÈTE > Enregistrer.
c) Dans index.html, remplace REMPLACER_PAR_LA_CLE_SITE_RECAPTCHA_V3 par la CLÉ DU SITE (elle est

d) Attends 24 h (le temps que tous les joueurs aient rechargé le nouveau code), puis
   App Check > API > Cloud Firestore > "Appliquer". À partir de là, une requête sans jeton valide
   (script dans la console, appel REST, ancienne version du jeu) est refusée.
   Ce que ça bloque : la triche "une ligne de console" et le spam de la base. Ce que ça ne
   bloque pas : un joueur qui modifierait le code du jeu dans son propre navigateur — les règles
   Firestore (bornes de temps, cohérence tracé/temps) sont là pour ça.
e) Pour tes tests en local : App Check > Applications > "Gérer les jetons de débogage". En
   local, ouvre F12 : le SDK affiche un jeton de débogage à coller dans la console Firebase.
   Ou plus simple : ne pas activer "Appliquer" avant d'avoir fini de tester.


ÉTAPE 4 — TESTER (30 min)
-------------------------
Sur ton téléphone, après réinstallation de l'icône :
  [ ] première ouverture : bannière "Statistiques d'utilisation" en bas (Accepter/Refuser). Le
      choix est mémorisé. Analytics ne démarre QUE si "Accepter". Pour la revoir :
      Chrome > Paramètres du site > Effacer les données.
  [ ] Compte > ⚙️ Réglages : Sons, Vibrations, "Voiture au-dessus du doigt", Mode gaucher.
  [ ] Compte > "📲 Installer l'application" n'apparaît que dans Chrome si l'appli n'est pas déjà
      installée (jamais dans l'appli installée elle-même, c'est normal).
  [ ] Course : sortir de piste = +2 s + le temps passé dehors compté double, chip rouge qui
      monte tant que le doigt est dans l'herbe. Couper un virage n'est plus rentable.
  [ ] Un checkpoint survolé en passant DANS l'herbe ne se valide plus (il faut être sur la
      piste).
  [ ] Mouvement très rapide à travers l'herbe : la pénalité tombe quand même (avant, un swipe
      rapide passait entre deux mesures).
  [ ] Arrivée : vibration longue + voile à damier.
  [ ] Résultat : ligne "Temps hors piste", étoiles ★ (1 tour uniquement) avec l'objectif suivant.
  [ ] Accueil : chip "★ x/180 · y %" et "🔥 Série" (à partir de 2 jours d'affilée). Étoiles sous
      chaque circuit (par difficulté sélectionnée).
  [ ] Bouton "🗓️ Défi du jour" : même circuit/réglages pour tout le monde, une tentative
      terminée par jour et par appareil, classement du jour séparé.
  [ ] Records : une seule ligne par joueur dans le classement de la semaine (son meilleur temps).
  [ ] Défis : bouton "🗑️ Supprimer" = premier tap rouge "Confirmer", second tap supprime (plus de
      popup native).
  [ ] Langues : passer en anglais/japonais/arabe → les textes se chargent (lang/xx.json) ; les
      nouveaux écrans (Réglages, Défi du jour, bannière) sont traduits.
  [ ] Connexion Google depuis l'appli installée : redirection (plus de popup), retour connecté.
Sur PC : F12 > Réseau : plus aucune adresse e-mail dans les réponses de "races_v2".

Test rapide sans publier à chaque fois : dans le dossier, "python -m http.server 8080", puis
chrome://inspect sur PC avec le téléphone en USB et "Port forwarding" 8080 → l'appli se charge
sur le téléphone à localhost:8080 (domaine autorisé par défaut dans Firebase Auth).


ÉTAPE 5 — À AJUSTER APRÈS QUELQUES SEMAINES DE JEU
--------------------------------------------------
- Objectifs 3 étoiles : constante STAR_SPEED dans index.html (vitesse en unités/s par
  difficulté : 230 / 190 / 150). Si presque personne n'atteint 3 ★, baisse les valeurs ; si tout
  le monde y arrive, monte-les. Regarde le classement hebdo : un bon objectif = le temps du
  5e-10e joueur.
- Temps minimal accepté par circuit : fonction minLapTime() dans firestore.rules (longueur du
  tracé / 600 u/s). Si un temps légitime est refusé (erreur "permission-denied" en console lors
  d'une course honnête très rapide), baisse le diviseur.
- Filtre de pseudos : tableau FORBIDDEN_NAME_PARTS dans index.html.
- Quota Firebase gratuit : Console > Utilisation. Le bandeau live coûte maintenant ~20 lectures
  par changement de réglage au maximum une fois par minute (cache 60 s + attente 400 ms), au
  lieu de 20 lectures par swipe. Si tu approches des 50 000 lectures/jour, augmente le cache à
  300 s (constante 60000 dans refreshLeaderGapMessageNow) et l'intervalle de 90 s des
  rafraîchissements (setInterval à la fin du script).

ÉTAPE 8 — GÉNÉRER L'APK/AAB ET PUBLIER (1 h)
--------------------------------------------
a) https://www.pwabuilder.com → colle l'URL du jeu → "Package for stores" > Android.
   - Package ID : io.github.julien67890.f1fingerrace (doit être IDENTIQUE à celui de
     .well-known/assetlinks.json)
   - App name : F1 Finger Race ; Launcher name : F1 Finger Race
   - Display mode : standalone ; Status bar color : #0e131a ; Splash : #0e131a
   - Signing key : "Create new" la première fois. TÉLÉCHARGE ET CONSERVE le fichier .keystore et
     les mots de passe : sans eux, impossible de publier une mise à jour plus tard.
   - Generate → un ZIP avec le .aab (pour Play), le .apk (pour tester), assetlinks.json et le
     keystore.
b) Ouvre l'assetlinks.json généré : copie l'empreinte SHA-256 dans
   .well-known/assetlinks.json de ton dépôt (à la place de REMPLACER_PAR_...), commit, push.
   ATTENTION : sur un sous-dossier GitHub Pages, ce fichier est servi à
   https://julien67890.github.io/F1-Finger-Race/.well-known/assetlinks.json, alors qu'Android
   le cherche à la RACINE du domaine : https://julien67890.github.io/.well-known/assetlinks.json.
   Deux solutions :
     1. crée un dépôt nommé exactement "Julien67890.github.io" (site racine de ton compte) avec
        juste le dossier .well-known/assetlinks.json et un fichier .nojekyll ; ou
     2. (mieux à terme) un nom de domaine à toi, pointé sur GitHub Pages — le fichier est alors
        naturellement à la racine, et le SEO en profite.
   Sans ce fichier à la racine, l'appli s'ouvre avec la barre d'adresse Chrome et Play refuse la
   fiche ("Digital Asset Links").
c) Installe le .apk sur ton téléphone (autoriser les sources inconnues) : l'appli doit s'ouvrir
   SANS barre d'adresse. Si elle s'ouvre avec, c'est l'assetlinks (b) qui n'est pas bon.
d) Play Console > Créer une application > importe le .aab dans "Tests internes", ajoute ton
   e-mail comme testeur, teste via le lien. Puis "Production" > envoyer en examen (1 à 7 jours).
e) Signature Play App Signing : accepte quand Play le propose ; il te donnera alors une SECONDE
   empreinte SHA-256 (celle de Google). Ajoute-la dans assetlinks.json à côté de la tienne (le
   tableau accepte plusieurs empreintes), sinon la version téléchargée depuis le Store s'ouvrira
   avec la barre d'adresse alors que ton APK de test était bon.


CE QUI A CHANGÉ DANS LE CODE (pour t'y retrouver)
-------------------------------------------------
Sécurité / conformité
- Champ "email" retiré des courses enregistrées (il était lisible par tous les joueurs).
- App Check (clé à coller, étape 3) ; règles Firestore de validation (firestore.rules).
- Analytics démarré uniquement après consentement (bannière, mémorisée, 11 langues).
- Filtre de pseudos (insultes évidentes, 11 langues) sur les 4 saisies de pseudo.
- Google : connexion par redirection quand l'appli est installée (popup sinon).

Gameplay / équité
- Masque de piste lu une fois en mémoire (plus de getImageData à chaque mouvement).
- Détection hors-piste ET checkpoints testés le long du segment entre deux positions du doigt.
- Pénalité = 2 s par sortie + temps passé hors piste × 2 (nouvelle ligne "Temps hors piste").
- Checkpoint validé uniquement sur la piste.
- Largeur d'affichage du circuit plafonnée à 430 px CSS : même difficulté physique sur tablette.
- Classement hebdo : une ligne par joueur ; ta ligne reconnue aussi en invité.
- Réglage "Voiture au-dessus du doigt" (40 px), vibrations différenciées (checkpoint, sortie,
  arrivée), voile à damier à l'arrivée, mode gaucher.

Progression
- Étoiles par circuit × difficulté (1 tour) : terminé / sans sortie / sous l'objectif.
- % de complétion, série de jours joués, défi du jour (collection "daily").

Technique
- Traductions en lang/*.json chargées à la demande (index.html : 355 → 238 Ko, dont 60 Ko de français intégré).
- CSS dans app.css. Service worker v6 avec pré-chargement. manifest : standalone, id, captures.
- Bandeau live : attente 400 ms + cache 60 s par réglage (lectures Firestore divisées par 10-20).
- Compte à rebours hebdo aligné sur l'heure de Paris (il était en UTC).
- Plus de alert()/confirm() natifs (toast traduit, suppression en deux taps).
- Bouton "Installer l'application", page : meta description, canonical, JSON-LD, Open Graph
  1200x630, preconnect polices.

Non inclus dans ce lot (lots suivants possibles) : export vidéo du rejeu, notifications push
(FCM), achats/boutique, musique de menu, domaine propre + pages par langue.

Détail à connaître : le fantôme (record perso ou adversaire) marque toujours un arrêt fixe de 2 s
à chaque sortie de piste pendant le rejeu, alors que la pénalité réelle inclut maintenant le
temps hors piste. Il termine donc son tracé un peu avant son vrai temps total puis reste immobile
sur la ligne jusqu'à ce temps — visuellement acceptable, à raffiner dans un prochain lot.
